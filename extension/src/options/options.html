AcademicReader Settings

Point AcademicReader at any LLM provider — Anthropic, OpenAI, Google, DeepSeek, or a self-hosted / OpenAI-compatible endpoint — by entering your own API key, base URL, and model below.

The provider name isn't just cosmetic — it must match your Model's prefix below (e.g. provider gemini with model gemini/gemini-2.5-pro), since that prefix is what this extension uses to decide which provider's API to call directly. For Google, use gemini (Google AI Studio API keys) — not google or vertex_ai, which needs GCP service-account credentials instead of a plain API key and isn't supported here.
Only needed for a custom / self-hosted OpenAI-compatible endpoint. Leave blank for standard hosted providers like Anthropic or OpenAI.
Stored locally via chrome.storage.local — isolated to this extension (inaccessible to web pages or other extensions) and sent only directly to the LLM provider you configure below, over HTTPS. Not shown once saved. For simplicity, you must re-enter it on every save, even when you're only changing another field like the model.
Must be provider-prefixed (e.g. anthropic/claude-opus-4-6, openai/gpt-5, gemini/gemini-2.5-pro, deepseek/deepseek-chat) — this extension uses that prefix to decide which provider's API to call directly. An unprefixed name like deepseek-chat will fail to resolve to any provider at all. Check the provider's own docs for current model names — the examples above may go stale. For a custom OpenAI-compatible endpoint, use openai/<your-model-name> together with a custom Base URL above.
Used for explaining figures/tables — leave blank to reuse Model above if it supports vision. Must also be provider-prefixed (see above). DeepSeek's chat/reasoner models have no vision support — if Model is a deepseek/ model, set this to a gemini/, anthropic/, or openai/ vision-capable model instead, or figure/table explanations will fail.
