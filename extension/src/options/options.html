AcademicReader Settings

Point AcademicReader at any LLM provider — Anthropic, OpenAI, Google, DeepSeek, a locally logged-in Codex or Claude CLI, or a self-hosted / OpenAI-compatible endpoint.

For Google, this uses AI Studio API keys — not vertex_ai, which needs GCP service-account credentials instead of a plain API key and isn't supported here.
Uses whatever ChatGPT account is signed in via codex login on this machine — no API key, and it draws on that subscription's included Codex usage instead of metered API billing. One-time setup required: run extension/native-host/register.sh once (Chrome can't launch local programs on its own — this registers a small bridge process it's allowed to launch on demand). Two trade-offs worth knowing: replies arrive all at once after a few seconds rather than streaming word-by-word, and each call carries meaningfully more overhead than a direct API call.
Uses whatever Claude account the claude CLI is signed in as on this machine — no API key, and it draws on that subscription's included usage instead of metered API billing. One-time setup required: run extension/native-host/register-claude.sh once (Chrome can't launch local programs on its own — this registers a small bridge process it's allowed to launch on demand). The CLI can stream, but this bridge returns each reply in one piece, so replies arrive all at once after a few seconds rather than word-by-word, and each call carries more overhead than a direct API call.
Only needed for a custom / self-hosted OpenAI-compatible endpoint. Leave blank for standard hosted providers like Anthropic or OpenAI.

Stored as a provider-prefixed model string internally (e.g. anthropic/claude-opus-4-6) — this extension uses that prefix to decide which provider's API to call directly. If you type a model manually, include the prefix yourself. For a custom OpenAI-compatible endpoint, use openai/<your-model-name> together with a custom Base URL above.
